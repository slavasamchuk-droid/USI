# Настройка админки без токенов у сотрудников

Сотрудники входят по **имени и общему паролю**. Токен GitHub хранится на сервере функции и в браузер не попадает. Аккаунт GitHub нужен только вам.

Время настройки — около 20 минут, разово.

---

## Шаг 1. Создать токен GitHub (один, для функции)

1. GitHub → аватар → **Settings** → внизу слева **Developer settings**
2. **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
3. Заполнить:
   - **Token name:** `usi-registry-proxy`
   - **Expiration:** 1 год (или «No expiration», если разрешено политикой)
   - **Repository access:** Only select repositories → выбрать **USIlinks**
   - **Permissions** → Repository permissions → **Contents: Read and write**
4. **Generate token** → скопировать строку `github_pat_…`

Токен показывается **один раз**. Сохраните его временно в заметках — он понадобится на шаге 3.

---

## Шаг 2. Создать функцию в Яндекс Облаке

1. Зайти на **console.yandex.cloud**, создать платёжный аккаунт (карта нужна, но при таких объёмах расход нулевой — бесплатного лимита в 1 000 000 вызовов в месяц хватит с большим запасом).
2. В каталоге выбрать **Cloud Functions** → **Создать функцию**.
3. Имя: `usi-registry`. **Создать**.
4. В открывшемся редакторе:
   - **Среда выполнения:** `python312`
   - **Способ:** Редактор кода
   - Создать файл `index.py` и вставить в него содержимое приложенного `proxy/index.py`
   - **Точка входа:** `index.handler`
   - **Таймаут:** 30 секунд
   - **Память:** 128 МБ

---

## Шаг 3. Задать переменные окружения

В том же окне, блок **Переменные окружения**, добавить семь строк:

| Ключ | Значение |
|---|---|
| `GH_TOKEN` | токен из шага 1 |
| `GH_OWNER` | `slavasamchuk-droid` |
| `GH_REPO` | `USIlinks` |
| `GH_BRANCH` | `main` |
| `GH_PATH` | `data.json` |
| `APP_PASS` | пароль, который вы дадите отделу |
| `ALLOW_ORIGIN` | `https://slavasamchuk-droid.github.io` |

Пароль в `APP_PASS` придумайте не короче 12 символов — он единственная защита на входе. Например `Usi-Reestr-2026!`.

**Создать версию.**

---

## Шаг 4. Открыть публичный вызов

1. Вкладка **Обзор** функции → переключатель **Публичная функция** → включить.
2. Скопировать адрес вида
   `https://functions.yandexcloud.net/d1a2b3c4d5e6f7g8h9i0`

Без этого шага админка не достучится до функции.

---

## Шаг 5. Прописать адрес в админке

Открыть `admin.html`, в начале скрипта найти:

```js
const CFG={
  PROXY : "ВСТАВЬТЕ_АДРЕС_ФУНКЦИИ",
};
```

Вставить адрес из шага 4. Сохранить, залить `admin.html` в репозиторий.

---

## Шаг 6. Проверить

1. Открыть админку, ввести имя и пароль.
2. Должен загрузиться реестр — 13 разделов, 99 материалов.
3. Изменить любую ссылку → **Сохранить и опубликовать**.
4. Через 1–2 минуты проверить сайт и кнопку **История** — там должна появиться запись с вашим именем.

Если вход не проходит: чаще всего забыт шаг 4 или в `ALLOW_ORIGIN` указан адрес, отличный от того, откуда открыта админка. Для проверки можно временно поставить `ALLOW_ORIGIN` в `*`.

---

## Что получают сотрудники

Только адрес админки и пароль. Ни аккаунта GitHub, ни токена, ни настроек. Имя вводится при входе и попадает в историю правок — видно, кто что менял.

## Смена пароля

Поменять `APP_PASS` в переменных функции, создать новую версию, разослать новый пароль. Старый перестаёт работать сразу.

## Что важно понимать про безопасность

- Токен лежит на сервере Яндекса и в браузер не отдаётся — вытащить его со страницы нельзя.
- Пароль **не проверяется на странице**, он уходит в функцию. Подобрать его, изучая код админки, невозможно.
- Функция умеет ровно четыре действия с одним файлом `data.json`. Даже зная пароль, посторонний не сможет тронуть остальной репозиторий.
- Худший сценарий при утечке пароля — испорченный реестр, который восстанавливается кнопкой «История» за минуту.

## Расходы

Cloud Functions: 1 000 000 вызовов и 10 ГБ×час в месяц бесплатно. Реестр правят несколько раз в неделю — вы не выйдете за бесплатный лимит. Счёт будет нулевым, но платёжный аккаунт с картой Яндекс требует при регистрации.
